Midterm Report • March 11

INTRO

For our semester project in CS460W, each student was tasked to form a group to make a website. The website would act as a college interface, allowing students, faculty, and administrators to view and edit schedules in one convenient location. They would also have to do a number of other tasks depending on their respective roles, such as a student changing a major and a faculty member approving or denying student co-op requests.

THINGS WE’VE DONE

After creating our group, the first order of business was to familiarize ourselves with the project requirements as well as create a meeting schedule and a group name. We all wrote down the requirements being asked of us, breaking them into manageable chunks to make the larger project seem less daunting. Around the same time, we also created our team's name, Mountain Coders. From the first week onward, we decided to come together in person on a weekly basis for a couple hours every Sunday morning. This schedule has persisted thus far.

The first order of business after our schedule was in order, was to decide on the foundations of the project. We decided to use a MySQL database as well as a PHP interface with CSS to create the mock website for the project. We then chose Data Science and Computer Science as our majors of focus, and English and Economics as our minors. At this point, we created a project GitHub as well as a GitHub Pages page for project progress.

During the next weeks, we focused on setting up the database tables as well as populating them with all the information they needed. This included major and minor requirements, usernames and passwords, and different roles each user could have. We also worked on linking these tables together to create an effective database infrastructure. Using this database setup, we were able to create the login page that the user would interface with. We populated a users table with each user and their information, creating passwords that fit the project requirements. Depending on the role of the user, the login page would then take the user to a different homepage. This would allow for different interface options between students, faculty, and administrators. Once the homepages were created, we then began creating a logout interface as well as other pages to host courses, profile information, and other important tasks that each role had to be able to complete.

This all brought us to the design aspect of the website. We each created a design prototype for what we thought the website should look like, and using that baseline, a final prototype was created that combined all the elements into one coherent site. Using CSS, we began making the website pages that we have already completed look more pleasing to the eye.
